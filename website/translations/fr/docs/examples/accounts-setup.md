# Exemple : inventorier tous les comptes d’une organisation

**Objectif :** un seul rapport qui couvre tous vos comptes, avec une colonne Account
et un contrôle des étiquettes.

**Ce qu’il vous faut :**

- un rôle portant le même nom (ici `InvenTagReadOnly`) dans chaque compte, avec une
  [politique en lecture seule](../guides/read-only-access.md#with-an-iam-role-in-each-account) ;
- les identifiants d’une identité autorisée à assumer ces rôles, par exemple dans le
  compte de gestion ou dans un compte de sécurité délégué.

## Modèle {#template}

Listez vos comptes :

```bash title="Terminal"
aws organizations list-accounts --query "Accounts[?Status=='ACTIVE'].[Id,Name]" --output text
```

Copiez le modèle intégré et renseignez-y vos comptes :

```bash title="Terminal"
inventag templates init org-multi-account --output .inventag/templates/our-org.yaml
```

```yaml title=".inventag/templates/our-org.yaml"
format_version: 1
kind: config
name: our-org
description: Every active account, read-only
spec:
  accounts:
    - account_id: "111111111111"
      account_name: Production
      role_arn: arn:aws:iam::111111111111:role/InvenTagReadOnly
    - account_id: "222222222222"
      account_name: Staging
      role_arn: arn:aws:iam::222222222222:role/InvenTagReadOnly
    - account_id: "333333333333"
      account_name: Shared services
      role_arn: arn:aws:iam::333333333333:role/InvenTagReadOnly
  regions: [us-east-1]
  outputs: [excel, word]
  report_template: standard-bom
  tag_policy: finops-cost-allocation
  max_concurrent_accounts: 4
```

## Commande {#command}

```bash title="Terminal"
inventag templates validate our-org
inventag --template our-org
```

## Sortie {#output}

Tant que les identifiants fictifs sont en place, `validate` vous avertit :

```text title="Terminal"
WARNING ~/acme-infra/.inventag/templates/our-org.yaml: account IDs 111111111111, 222222222222, 333333333333 look like placeholders; replace them with your own
OK    ~/acme-infra/.inventag/templates/our-org.yaml (config 'our-org')
```

L’exécution, avec un bucket d’exemple dans chacun des trois comptes fictifs :


## Étapes suivantes {#next-steps}

- Si un compte échoue, InvenTag journalise l’erreur, rend compte des autres comptes et
  se termine tout de même avec le code 0 ; consultez donc le journal. La cause habituelle
  est la politique d’approbation du rôle.
- [Analyser plusieurs comptes](../guides/scan-multiple-accounts.md) explique les
  options de réglage.
