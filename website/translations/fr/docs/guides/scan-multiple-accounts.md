# Analyser plusieurs comptes

**À qui s’adresse cette page :** vous gérez plusieurs comptes AWS et vous voulez un seul rapport
consolidé.

**Ce que vous saurez faire après lecture :** lister vos comptes une fois et les analyser tous
en une seule exécution.

## Comment ça marche {#how-it-works}

InvenTag lit une liste de comptes. Pour chacun, il obtient des identifiants, soit
à partir d’un profil AWS CLI nommé, soit en assumant un rôle IAM depuis l’identité avec laquelle vous
l’exécutez. Il analyse chaque compte, quatre à la fois par défaut, et
écrit un seul rapport avec une colonne Account.

InvenTag ne liste pas pour vous les comptes de votre AWS Organization. Vous
écrivez la liste.

## 1. Créer un rôle en lecture seule dans chaque compte {#1-create-a-read-only-role-in-every-account}

Suivez [Configurer un accès en lecture seule](./read-only-access.md#with-an-iam-role-in-each-account).
Utilisez le même nom de rôle partout, par exemple `InvenTagReadOnly`.

## 2. Obtenir votre liste de comptes {#2-get-your-account-list}

Depuis le compte de gestion, ou un compte d’administrateur délégué :

```bash
aws organizations list-accounts \
  --query "Accounts[?Status=='ACTIVE'].[Id,Name]" --output text
```

## 3. Écrire la liste sous forme de modèle de configuration {#3-write-the-list-as-a-config-template}

```bash
inventag templates init org-multi-account --output .inventag/templates/our-org.yaml
```

Modifiez la section `accounts`. Chaque compte a besoin de son identifiant à 12 chiffres **entre guillemets**
et d’un `role_arn` ou d’un `profile_name` :

```yaml
spec:
  accounts:
    - account_id: "123456789012"
      account_name: Production
      role_arn: arn:aws:iam::123456789012:role/InvenTagReadOnly
    - account_id: "210987654321"
      account_name: Development
      profile_name: dev-readonly
  regions: [us-east-1, eu-west-1]
```

Vérifiez-le, puis lancez l’analyse :

```bash
inventag templates validate our-org
inventag --template our-org
```

`validate` détecte les erreurs courantes : identifiants de compte sans guillemets, ARN de rôle qui
pointe vers un autre compte que `account_id`, et clés d’accès dans le fichier
(interdites dans les modèles). Avec les identifiants fictifs encore en place, il affiche
(données d’exemple) :

```text title="Terminal"
WARNING ~/acme-infra/.inventag/templates/our-org.yaml: account IDs 111111111111, 222222222222, 333333333333 look like placeholders; replace them with your own
OK    ~/acme-infra/.inventag/templates/our-org.yaml (config 'our-org')
```

Une exécution sur les trois comptes d’exemple :

```text title="Terminal"
Wrote bom_output/tag_compliance_20261112_090000.json
Wrote bom_output/multi_account_bom_20261112_090000.docx
Wrote bom_output/multi_account_bom_20261112_090000.xlsx
Tag policy 'finops-cost-allocation': 0 of 36 resources compliant (0.0%), 36 non-compliant, 42 out of scope.
```

**Feuilles :** `Summary`, `EVENTS`, `KMS`, `S3`, `VPC`, `Tag Compliance`

## Ou utiliser un fichier de comptes {#or-use-an-accounts-file}

L’option `--accounts-file` fonctionne aussi, et elle accepte des clés d’accès (évitez-les
si possible). Si tous les comptes utilisent le même nom de rôle, vous n’avez pas besoin d’écrire
chaque ARN :

```bash title="Terminal"
inventag --accounts-file accounts.yaml --cross-account-role InvenTagReadOnly --create-excel
```

Le format du fichier de comptes est décrit dans [Fichiers de configuration](../reference/configuration-files.md#accounts-file).

```bash
inventag --accounts-file accounts.yaml --create-excel
```

## Ajuster l’exécution {#tune-the-run}

| Réglage | Champ du modèle de configuration | Option |
|---|---|---|
| Comptes analysés simultanément (4 par défaut) | `max_concurrent_accounts` | `--max-concurrent-accounts` |
| Secondes autorisées par compte (1800 par défaut) | `account_processing_timeout` | `--account-processing-timeout` |
| Un compte à la fois | `parallel_processing: false` | `--disable-parallel-processing` |

Si un compte échoue, par exemple parce que son rôle ne peut pas être assumé,
InvenTag journalise l’erreur et rapporte les comptes qui ont fonctionné. Il ne
se rabat pas sur vos identifiants par défaut pour ce compte. **L’exécution se termine quand même
avec le code 0, et le rapport ne nomme pas le compte manquant.** Cherchez dans le
journal `Failed to establish context for account`. Si tous les comptes échouent, l’
exécution se termine avec le code 1 et n’écrit aucun rapport.
