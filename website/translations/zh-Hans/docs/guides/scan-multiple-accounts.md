# 扫描多个账户

**适合谁阅读：** 你管理不止一个 AWS 账户，想得到一份合并的报告。

**读完后你可以：** 把账户列出一次，并在一次运行中全部扫描。

## 工作原理 {#how-it-works}

InvenTag 读取一份账户列表。对每个账户，它要么从指定的 AWS CLI 配置文件（profile）获取凭证，
要么用你运行它时所用的身份去代入一个 IAM 角色。它会扫描每个账户（默认最多同时扫描四个），
并写出一份带有 Account 列的报告。

InvenTag 不会替你列出 AWS Organization 中的账户。这份列表需要你自己写。

## 1. 在每个账户中创建只读角色 {#1-create-a-read-only-role-in-every-account}

请按照[设置只读访问](./read-only-access.md#with-an-iam-role-in-each-account)操作。
所有账户使用同一个角色名称，例如 `InvenTagReadOnly`。

## 2. 获取账户列表 {#2-get-your-account-list}

在管理账户或委派管理员账户中：

```bash
aws organizations list-accounts \
  --query "Accounts[?Status=='ACTIVE'].[Id,Name]" --output text
```

## 3. 把列表写成配置模板 {#3-write-the-list-as-a-config-template}

```bash
inventag templates init org-multi-account --output .inventag/templates/our-org.yaml
```

编辑 `accounts` 部分。每个账户都需要它的 12 位 ID（**要加引号**），
以及 `role_arn` 或 `profile_name` 之一：

```yaml
spec:
  accounts:
    - account_id: "123456789012"
      account_name: Production
      role_arn: arn:aws:iam::123456789012:role/InvenTagReadOnly
    - account_id: "210987654321"
      account_name: Development
      profile_name: dev-readonly
  regions: [us-east-1, eu-west-1]
```

先检查，再运行：

```bash
inventag templates validate our-org
inventag --template our-org
```

`validate` 能发现常见的错误：没有加引号的账户 ID、指向与 `account_id` 不同账户的角色 ARN，
以及文件中的访问密钥（模板中不允许）。如果仍保留着占位符 ID，它会提示（示例数据）：

```text title="Terminal"
WARNING ~/acme-infra/.inventag/templates/our-org.yaml: account IDs 111111111111, 222222222222, 333333333333 look like placeholders; replace them with your own
OK    ~/acme-infra/.inventag/templates/our-org.yaml (config 'our-org')
```

针对三个示例账户的一次运行：

```text title="Terminal"
Wrote bom_output/tag_compliance_20261112_090000.json
Wrote bom_output/multi_account_bom_20261112_090000.docx
Wrote bom_output/multi_account_bom_20261112_090000.xlsx
Tag policy 'finops-cost-allocation': 0 of 36 resources compliant (0.0%), 36 non-compliant, 42 out of scope.
```

**工作表：** `Summary`、`EVENTS`、`KMS`、`S3`、`VPC`、`Tag Compliance`

## 或者使用账户文件 {#or-use-an-accounts-file}

`--accounts-file` 选项同样可用，并且它接受访问密钥（如果可以，请避免使用）。
如果每个账户使用相同的角色名称，就不需要逐个写出 ARN：

```bash title="Terminal"
inventag --accounts-file accounts.yaml --cross-account-role InvenTagReadOnly --create-excel
```

账户文件的格式见[配置文件](../reference/configuration-files.md#accounts-file)。

```bash
inventag --accounts-file accounts.yaml --create-excel
```

## 调整运行 {#tune-the-run}

| 设置 | 配置模板字段 | 参数 |
|---|---|---|
| 同时扫描的账户数（默认 4） | `max_concurrent_accounts` | `--max-concurrent-accounts` |
| 每个账户允许的秒数（默认 1800） | `account_processing_timeout` | `--account-processing-timeout` |
| 一次一个账户 | `parallel_processing: false` | `--disable-parallel-processing` |

如果某个账户失败，例如因为无法代入它的角色，InvenTag 会记录错误，并报告成功的那些账户。
它不会对该账户回退到你的默认凭证。**运行仍然以退出码 0 退出，而且报告不会指出缺少的账户。**
请在日志中搜索 `Failed to establish context for account`。如果所有账户都失败，
运行会以退出码 1 退出，并且不写出任何报告。
